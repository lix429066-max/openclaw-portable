## 🎯 什么是 Heartbeat？

**Heartbeat** 是定期发送的检查消息，用于：
- ✅ 确认系统运行正常
- ✅ 提醒无涯检查是否有需要关注的事项
- ✅ 保持会话活跃

**触发方式**: 用户发送特定的 Heartbeat 提示消息

---

## 📋 Heartbeat 响应规范

### ✅ 当一切正常时

**响应**: `HEARTBEAT_OK`

**说明**:
- 所有核心功能正常
- 没有待处理的任务
- 没有需要关注的错误

**静默时段 (23:00-07:00)**: 深夜非严重问题直接 `HEARTBEAT_OK`，只有 critical（gateway 挂、cron 全停、API key 失效）才详细报告。逍遥在睡觉，别吵 🦞

**示例**:
```
HEARTBEAT_OK
```

### ⚠️ 当有需要关注的事项时

**响应**: 直接列出需要关注的事项

**格式**:
```
[优先级] 事项描述 + 建议行动

例如:
[高] TTS 语音生成失败 - 需要检查 edge-tts 配置
[中] browser 端口耗尽 - 建议重启网关
[低] 旧日志文件清理 - 建议本周内完成
```

## 🧠 检查清单

每次收到 Heartbeat 时，按顺序检查：

### 1️⃣ 核心功能状态
- [ ] 代码编写能力正常
- [ ] 搜索工具正常 (Tavily)
- [ ] TTS 语音生成正常 (edge-tts)
- [ ] GitHub 操作正常
- [ ] 浏览器自动化正常
- [ ] 文件读写正常

### 2️⃣ 已知问题
- [ ] 检查是否有未解决的技术问题
- [ ] 检查是否有待处理的错误
- [ ] 检查是否有需要记录的教训

### 3️⃣ 待办事项
- [ ] 检查是否有未完成的任务
- [ ] 检查是否有计划中的工作
- [ ] 检查是否有用户要求的后续行动

### 4️⃣ 系统健康
- [ ] 检查磁盘空间
- [ ] 检查网络连接
- [ ] 检查 API 密钥有效性

## 🎯 响应原则

### ✅ 应该做的
- **简洁**: 只列出需要关注的事项
- **具体**: 说明问题和可能的解决方案
- **优先级**: 按优先级排序（高 > 中 > 低）
- **诚实**: 有问题就说问题，没问题就 OK

### ❌ 不应该做的
- **啰嗦**: 不要长篇大论解释
- **模糊**: 不要说"可能"、"也许"
- **隐瞒**: 有问题要如实报告
- **过度**: 不要对小事大惊小怪

## 🦾 KAIROS 模式 (2026-05-11 整合)

> 灵感来自 Claude Code 泄露源码中的 KAIROS 常驻后台守护

### Tick 检查扩展

收到 Heartbeat 时，除基本检查外，还应执行：

| 检查项 | 频率 | 说明 |
|--------|------|------|
| MAGIC_DOC 文件同步 | 每次 | 检查标记文件是否需要更新 |
| 记忆审计 (autoDream) | 每日 | 验证 MEMORY.md 声明的数字/状态 vs 实际 |
| 技能数量同步 | 每周 | TOOLS.md vs 实际 skills/ 目录 |
| 配置备份检查 | 每周 | 确认 backup/ 有最近 3 个版本 |
| 过期文件清理 | 每周 | memory/ 超过 30 天的文件 |

### 空闲时的主动行为

- 发现 MAGIC_DOC 文件过时 → 自动更新日期/版本/数据
- 发现记忆与实际不符 → 修正记忆
- 发现未记录的教训 → 写入 memory/今日.md
